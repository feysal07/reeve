  helm test {{ .Release.Name }} --namespace {{ .Release.Namespace }}

Point an agent at it. From inside the cluster:

  OTEL_EXPORTER_OTLP_ENDPOINT=http://{{ include "reeve-collector.fullname" . }}.{{ .Release.Namespace }}.svc:{{ .Values.service.port }}
{{- if .Values.ingress.enabled }}

From a developer machine:
{{- range .Values.ingress.hosts }}

  OTEL_EXPORTER_OTLP_ENDPOINT=https://{{ .host }}
{{- end }}
{{- else }}

Agents run on developer machines, which are outside the cluster. Nothing can reach
this collector from there yet. Enable the Ingress, or forward the port to try it:

  kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "reeve-collector.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
{{- end }}

Read what it has collected. The image has no shell, so the binary is named in full:

  kubectl --namespace {{ .Release.Namespace }} exec {{ include "reeve-collector.fullname" . }}-0 -- /usr/local/bin/reeve report --store {{ include "reeve-collector.storePath" . }} --since 168h
{{ if .Values.collector.metrics.enabled }}
Metrics are served on their own port and their own Service, never on the one agents
export to, so exposing that one cannot publish these along with it:

  kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "reeve-collector.fullname" . }}-metrics {{ .Values.collector.metrics.port }}:{{ .Values.collector.metrics.port }}

{{- if not .Values.persistence.enabled }}
WARNING: persistence is disabled. The event store is an emptyDir, so the audit
record is deleted when the pod restarts, is rescheduled, or is upgraded. Fine for
trying the chart out; not a way to run it.
{{ end }}
{{- if not (include "reeve-collector.teamsConfigMap" .) }}
WARNING: no team mapping. Every event will land in the unattributed bucket, and
the cost report will show one team. Set collector.teams.content, or point
collector.teams.existingConfigMap at a ConfigMap holding a teams.yaml key.
{{ end }}
{{- if not (include "reeve-collector.pricesConfigMap" .) }}
WARNING: no price table, so costs are computed at published list rates. They will
be wrong for any negotiated agreement and they go out of date. Supply your own
before anyone charges a team for them.
{{ end }}
{{- if and .Values.ingress.enabled (not .Values.networkPolicy.enabled) }}
NOTE: the collector is reachable through the Ingress and has no authentication of
its own. You confirmed authentication is enforced in front of it. If that stops
being true, anything that can reach the endpoint can write events under any
identity, and a forged event is indistinguishable from a real one.
{{ end }}
{{- if not .Values.collector.metrics.enabled }}
NOTE: metrics are off, so nothing reports whether this collector is still receiving
anything. An agent that cannot export mostly carries on working, which means a
collector that has gone quiet looks exactly like an organisation with nothing to
report. Set collector.metrics.enabled=true.
{{ else }}
Nothing prunes the event file; it only grows. Watch it through the metrics rather
than by looking at the file:

  reeve_store_size_bytes
  time() - reeve_store_modified_timestamp_seconds

The second is the one that catches a collector that has stopped receiving, which is
otherwise indistinguishable from a quiet week.
{{- if not .Values.prometheusRule.enabled }}

Alerts for both, and for four other things worth knowing about, ship with this
chart: set prometheusRule.enabled=true if you run the Prometheus operator.
{{- end }}
{{ end }}
